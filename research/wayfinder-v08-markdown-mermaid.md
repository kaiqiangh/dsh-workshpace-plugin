# Finding: Markdown and Mermaid preview boundary

Issue: https://github.com/kaiqiangh/dsh-workshpace-plugin/issues/133  
Evidence baseline: `research/markdown-mermaid` at `83af760efc73ae87039ae443d929f65b23282abb`; source and checked-in `lib/` were inspected without changing product code.

## Decision-relevant finding

The carrier has a real, bounded Markdown renderer, but Mermaid is not currently a faithful rendered-preview capability. Two independent release/runtime blockers exist:

1. `WorkspaceMarkdown` emits `<pre class="language-mermaid">`, while the enhancer queries `pre code.language-mermaid`. The selector therefore finds zero Mermaid blocks even when the DOM and vendor route are available. The checked-in client bundle contains the same mismatch: emitted `pre` class at [`lib/client.js#L7277`](https://github.com/kaiqiangh/dsh-workshpace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/lib/client.js#L7277) versus selector at [`lib/client.js#L7380`](https://github.com/kaiqiangh/dsh-workshpace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/lib/client.js#L7380).
2. The build copies `node_modules/mermaid/dist/mermaid.min.js` into `lib/assets` ([`scripts/build.mjs#L86-L99`](https://github.com/kaiqiangh/dsh-workshpace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/scripts/build.mjs#L86-L99)), and the Host route expects that file ([`src/host/workspace-resource.ts#L29-L83`](https://github.com/kaiqiangh/dsh-workshpace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/src/host/workspace-resource.ts#L29-L83)). However, the package `files` allow-list omits `lib/assets` ([`package.json#L9-L21`](https://github.com/kaiqiangh/dsh-workshpace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/package.json#L9-L21)). `npm pack --dry-run --json` reported `entryCount: 49` and only `lib/types/web/workspace-mermaid.d.ts` under the Mermaid/assets filter; it did not include `lib/assets/mermaid.min.js` (the checked-in file is 3,566,058 bytes). An installed package therefore makes the vendor route return its 404 fallback, and the browser leaves Mermaid as code.

These blockers are not caught by the current tests. The Markdown tests verify the generated fence attributes, while the Mermaid tests verify the fixed URL/theme and Node fallback; neither mounts a DOM and exercises `enhanceMermaidBlocks` against the generated HTML ([`tests/workspace-markdown.test.ts#L21-L26`](https://github.com/kaiqiangh/dsh-workshpace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/tests/workspace-markdown.test.ts#L21-L26), [`tests/workspace-mermaid-i18n.test.ts#L7-L50`](https://github.com/kaiqiangh/dsh-workshpace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/tests/workspace-mermaid-i18n.test.ts#L7-L50)).

## What the current carrier actually supports

### Markdown

- The descriptor is `type: "markdown"`, bounded text content, `truncated`, and a policy declaring raw HTML and remote images disabled; the descriptor still labels the renderer `"ui-primitives"`, although the client deliberately uses the custom `WorkspaceMarkdown` renderer rather than `MarkdownText` ([`src/domain/preview.ts#L83-L100`](https://github.com/kaiqiangh/dsh-workshpace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/src/domain/preview.ts#L83-L100), [`src/web/workspace-preview-adapters.ts#L120-L139`](https://github.com/kaiqiangh/dsh-workshpace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/src/web/workspace-preview-adapters.ts#L120-L139)).
- The implemented GFM subset is headings, paragraphs, fenced/inline code, bold/italic/strike, inline links/images, flat ordered/unordered lists, one-level blockquotes, horizontal rules, and simple tables ([`src/web/workspace-markdown.ts#L1-L15`](https://github.com/kaiqiangh/dsh-workshpace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/src/web/workspace-markdown.ts#L1-L15), [`src/web/workspace-markdown.ts#L219-L352`](https://github.com/kaiqiangh/dsh-workshpace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/src/web/workspace-markdown.ts#L219-L352)). This is not a full CommonMark/GFM implementation: nested lists, reference links, link titles, tilde fences, multi-backtick spans, task-list semantics, and richer table parsing are outside the code path.
- Input HTML is escaped before the renderer emits its own tags, and link/image protocols reject `javascript:`, `data:`, `vbscript:`, and other explicit schemes ([`src/web/workspace-markdown.ts#L18-L25`](https://github.com/kaiqiangh/dsh-workshpace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/src/web/workspace-markdown.ts#L18-L25), [`src/web/workspace-markdown.ts#L105-L120`](https://github.com/kaiqiangh/dsh-workshpace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/src/web/workspace-markdown.ts#L105-L120)).
- There is a policy mismatch: ADR-0005 says relative links are inert, but `safeWorkspaceUrl` accepts scheme-less relative targets and `renderWorkspaceInline` emits them as active links with `target="_blank"` ([`docs/adr/0005-bounded-preview-and-opaque-resources.md#L5-L9`](https://github.com/kaiqiangh/dsh-workshpace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/docs/adr/0005-bounded-preview-and-opaque-resources.md#L5-L9), [`src/web/workspace-markdown.ts#L167-L180`](https://github.com/kaiqiangh/dsh-workshpace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/src/web/workspace-markdown.ts#L167-L180)). v0.8 must choose either the ADR contract (inert relative links) or update the policy text.

### Same-origin opaque images

- The Host scans inline relative image syntax and creates an `imageUrls` object crossing the Typert boundary; the client only emits an image when that map contains the source ([`src/host/workspace-artifacts.ts#L281-L294`](https://github.com/kaiqiangh/dsh-workshpace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/src/host/workspace-artifacts.ts#L281-L294), [`src/web/workspace-preview-adapters.ts#L125-L134`](https://github.com/kaiqiangh/dsh-workshpace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/src/web/workspace-preview-adapters.ts#L125-L134)). Remote images and unresolved/escaping images become alt text rather than network fetches.
- Relative image resolution is directory-aware, rejects root escapes and symlink escapes through the Preview resolver, accepts only media types beginning with `image/`, and enforces the image byte limit before minting a short-lived opaque resource ([`src/domain/preview.ts#L433-L479`](https://github.com/kaiqiangh/dsh-workshpace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/src/domain/preview.ts#L433-L479)). Resource open rechecks identity, version, type, containment, size, expiry, and disposal; the route never accepts a raw filesystem path ([`docs/adr/0005-bounded-preview-and-opaque-resources.md#L5-L9`](https://github.com/kaiqiangh/dsh-workshpace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/docs/adr/0005-bounded-preview-and-opaque-resources.md#L5-L9), [`src/host/workspace-resource.ts#L155-L225`](https://github.com/kaiqiangh/dsh-workshpace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/src/host/workspace-resource.ts#L155-L225)).
- There is one safety inconsistency to resolve: normal `.svg` preview is explicitly rejected as `svg-sanitization-required`, but `markdownImageUrl()` uses `mediaTypeFor()` plus `startsWith("image/")`, and `mediaTypeFor(".svg")` is `image/svg+xml`; a relative Markdown SVG can therefore receive an opaque URL despite the general SVG rejection ([`src/domain/preview.ts#L214-L230`](https://github.com/kaiqiangh/dsh-workshpace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/src/domain/preview.ts#L214-L230), [`src/domain/preview.ts#L384-L390`](https://github.com/kaiqiangh/dsh-workshpace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/src/domain/preview.ts#L384-L390), [`src/domain/preview.ts#L441-L479`](https://github.com/kaiqiangh/dsh-workshpace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/src/domain/preview.ts#L441-L479)). The v0.8 contract should reject SVG here too unless a dedicated sanitizer is added.

### Mermaid loading, safety, truncation, and fallback

- The intended route is fixed and same-origin: `/workspace/vendor/mermaid.js`. The client injects one async script, initializes Mermaid with `startOnLoad: false`, `securityLevel: "strict"`, and `suppressErrorRendering: true`, and limits enhancement to the first 16 matched fences ([`src/web/workspace-mermaid.ts#L11-L18`](https://github.com/kaiqiangh/dsh-workshpace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/src/web/workspace-mermaid.ts#L11-L18), [`src/web/workspace-mermaid.ts#L58-L85`](https://github.com/kaiqiangh/dsh-workshpace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/src/web/workspace-mermaid.ts#L58-L85), [`src/web/workspace-mermaid.ts#L117-L129`](https://github.com/kaiqiangh/dsh-workshpace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/src/web/workspace-mermaid.ts#L117-L129)). There is no repository-side per-diagram source-length budget, and blocks after the first 16 remain raw without a count.
- Missing `document`, vendor route failure, or a missing global `mermaid` resolves loading to `false`; Mermaid render errors keep the original `<pre>` code. `WorkspaceMarkdownView` ignores the enhancer's returned count, so users get no visible “diagram unavailable” status—only raw code ([`src/web/workspace-mermaid.ts#L88-L129`](https://github.com/kaiqiangh/dsh-workshpace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/src/web/workspace-mermaid.ts#L88-L129), [`src/web/workspace-preview-adapters.ts#L154-L168`](https://github.com/kaiqiangh/dsh-workshpace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/src/web/workspace-preview-adapters.ts#L154-L168)). This raw-code fallback is good for readability, but it must be an explicit, localized fallback in the v0.8 contract.
- Markdown text uses a 2 MiB default and 8 MiB hard ceiling; the content is sliced to the configured limit and marks `truncated`, while the UI appends a truncation status ([`src/domain/preview.ts#L7-L23`](https://github.com/kaiqiangh/dsh-workshspace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/src/domain/preview.ts#L7-L23), [`src/domain/preview.ts#L396-L408`](https://github.com/kaiqiangh/dsh-workshspace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/src/domain/preview.ts#L396-L408), [`src/web/workspace-preview-adapters.ts#L102-L110`](https://github.com/kaiqiangh/dsh-workshspace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/src/web/workspace-preview-adapters.ts#L102-L110)). A truncated fence can consequently remain raw or be parsed from incomplete source; there is no Mermaid-specific truncation notice.
- The Host installs the opaque resource and vendor routes only inside the `webServer?.register` branch. A carrier without the public WebServer can still return preview data, but relative images and Mermaid have no same-origin route ([`src/index.ts#L368-L379`](https://github.com/kaiqiangh/dsh-workshpace-plugin/blob/83af760efc73ae87039ae443d929f65b23282abb/src/index.ts#L368-L379)). The fixed root-relative client URL also assumes the Harness exposes that exact path.

### Zero-runtime-dependency claim

The claim is accurate only in the narrow npm-dependency sense: `mermaid` is a `devDependency`, not a package `dependency`, and the browser client does not import it; the build intends to ship a static vendor file. It is not currently accurate as a shipped capability because the package allow-list drops that required file. The minimal release gate is: build, `npm pack --dry-run`, assert `lib/assets/mermaid.min.js` is present, then assert the route returns JavaScript and the client can render one diagram in a DOM-backed test.

## Minimal v0.8 renderer contract

1. Keep `type: "markdown"`, but name the actual renderer boundary explicitly (or document why `"ui-primitives"` means a Workspace wrapper).
2. Define the supported Markdown subset above; escape raw HTML, drop remote images, reject SVG relative images, and make relative links inert to match ADR-0005.
3. Resolve only in-root raster images through identity/version/TTL-bound opaque URLs.
4. Make Mermaid matching, vendor packaging, route availability, strict initialization, and raw-code fallback an end-to-end acceptance path; show a localized fallback when the vendor is unavailable or rendering fails.
5. Add tests for generated-HTML-to-enhancer matching, a stubbed successful SVG replacement, failed vendor load, failed render, 17-fence behavior, truncated Mermaid, packaged vendor presence, and relative SVG rejection.

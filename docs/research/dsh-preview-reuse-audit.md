# DSH preview and deliverables reuse audit

Research snapshot: 2026-08-15. Primary sources are DeepSeek Harness commit [`47f943859bef60e4160492346772ded9b24f765a`](https://github.com/deepseek-ai/deepseek-harness/tree/47f943859bef60e4160492346772ded9b24f765a) and the first-party npm registry metadata/tarballs for `0.1.0-rc.6`.

## Decision

For DSH Workspace v0.1:

- **Wrap and reuse** `MarkdownText`, `CodeBlock`, and `JsonTree` from `@deepseek-ai/dsh-client-ui-primitives` behind Workspace-owned preview components. The Workspace host remains responsible for path authorization, byte limits, decoding, and JSON parsing.
- **Remain independent** for plain text, CSV, image, PDF, and generic binary resources. Native browser elements cover plain text/image; no current first-party CSV/PDF/general-resource renderer exists.
- **Keep artifact derivation independent but compatible** with `@deepseek-ai/dsh-client-ui-deliverables`. Do not register a second produced-files row or treat its turn-scoped mutation list as the Workspace session artifact index.
- Pin all reused Harness packages to one exact release train. As of the snapshot, npm `latest` is `0.0.1-rc.1` while `next` is `0.1.0-rc.6`; an unqualified install selects the older API ([dist-tags](https://registry.npmjs.org/-/package/@deepseek-ai/dsh-client-ui-primitives/dist-tags)).

## Package and bundle implications

- The audited `next` packages are prerelease `0.1.0-rc.6` and MIT-licensed: [ui-primitives metadata](https://registry.npmjs.org/@deepseek-ai%2Fdsh-client-ui-primitives/0.1.0-rc.6), [ui-attachment metadata](https://registry.npmjs.org/@deepseek-ai%2Fdsh-client-ui-attachment/0.1.0-rc.6), and [ui-deliverables metadata](https://registry.npmjs.org/@deepseek-ai%2Fdsh-client-ui-deliverables/0.1.0-rc.6).
- Registry unpacked sizes are approximately 395 kB for ui-primitives, 38 kB for ui-attachment, and 42 kB for ui-deliverables. These are package sizes, not browser transfer sizes. ui-primitives brings Markdown/micromark, KaTeX, Shiki/languages, React, and supporting dependencies; the shipped Web app deliberately separates Markdown/math/highlight vendor families ([Vite config](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/apps/web/vite.config.ts#L20-L67)).
- Reusing ui-primitives is still the smaller maintenance surface because Harness Web already consumes it. DSH Workspace should import only public package roots, pin the exact RC, and keep one local adapter per reused component so API churn does not leak into preview providers.
- Do not add ui-attachment or attachment-local merely for Workspace image display. The former couples to the attachment DTO/package; the latter adds `sharp`, durable-copy semantics, and limits that do not match the PRD ([package](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/packages/attachment/attachment-local/package.json)).

## Required checks before implementation

1. Confirm the target Harness composition resolves all reused packages to the same exact RC and that its client bundler deduplicates React.
2. Test Markdown remote-image behavior against the chosen Workspace privacy policy.
3. Prove host byte/row/node limits before mounting Markdown, Shiki, JSON, CSV, image, or PDF UI.
4. Treat the general binary resource seam as unresolved until the separate host/Web extension spike identifies a supported public carrier mechanism.
